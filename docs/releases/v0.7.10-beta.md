# QStar v0.7.10 Beta

QStar v0.7.10 Beta is a public prerelease patch for the 0.7 beta line. It keeps
the runtime surface compatible with v0.7.0-beta through v0.7.9-beta while
closing the next Windows publish gate issue found during the official
`windows-x86_64.zip` release path.

Runtime version:

```txt
qstar 0.7.10-beta
```

## Release Decision

This patch release exists because `v0.7.9-beta` made the toolset provider
namespace path tool visible to the Windows process runner, allowing the Stella
side of the broad smoke fixture to pass and the Ninja side to build
successfully. The next failure was not an execution failure: the Ninja build
reported `status ok`, but the cross-platform smoke still required the
POSIX-style wrapper runtime log to contain every wrapper marker on Windows.

The fixture now keeps the backend contract checks that matter on Windows:

- generated Ninja graph emission
- provider tool wrappers present in `build.ninja`
- `backend ninja`
- `status ok`

The wrapper runtime log assertions remain on non-Windows hosts, where the
POSIX shell environment and file logging behavior are stable enough for that
extra assertion.

The `v0.7.0-beta`, `v0.7.1-beta`, `v0.7.2-beta`, `v0.7.3-beta`,
`v0.7.4-beta`, `v0.7.5-beta`, `v0.7.6-beta`, `v0.7.7-beta`,
`v0.7.8-beta`, and `v0.7.9-beta` tags must not be moved. Instead,
`v0.7.10-beta` is the first 0.7 patch tag that contains:

- the Q253 Windows publish/download smoke path
- Windows default executable/test `.exe` artifact naming in the graph artifact
  map and cache output list
- a Windows daemon deferred status line compatible with the cross-platform
  smoke contract
- Windows-aware smoke expectations for executable artifact paths in Stella,
  Ninja, action-description, replay, command argv, and project fixture checks
- a Windows skip for the legacy inline Ninja mini-block in `tests/smoke.sh`,
  with dedicated Windows Ninja/execution corpora left as the actual coverage
- MSYS2 argv conversion protection for QStar label arguments in the broad smoke
  script using the literal `//` prefix
- clearer import/module and toolset-wire diagnostics in the smoke harness
- host compiler selection for the toolset provider namespace wire corpus
- a Windows-findable `toolset-gen.sh` path tool in the toolset provider
  namespace wire corpus
- Windows-aware Ninja wrapper log expectations for the toolset provider
  namespace wire corpus

## Highlights

- Keeps `.exe` as the correct default Windows executable/test artifact suffix.
- Keeps the broad smoke script cross-platform while preserving QStar label
  arguments under MSYS2.
- Keeps toolset provider namespace tests independent of a `cc` alias.
- Keeps path-tool lookup explicit enough for Windows `CreateProcess`.
- Keeps Windows Ninja checks focused on generated graph wiring and successful
  backend execution.
- Leaves Windows Ninja behavior covered by the dedicated parity and execution
  corpora.
- Keeps GitHub Release mutation explicit: Windows upload runs only from
  `workflow_dispatch` with `publish_windows_asset=true`.
- Downloaded Windows zip smoke verifies `bin/qstar.exe`, docs/man files,
  bundled language providers, `qstar init app`, Zig provider vendoring, Stella
  build, and Ninja build from the extracted release tree.
- macOS and Linux remain ordinary 0.7 beta release assets.
- Daemon remains beta opt-in. Windows named pipe daemon support remains
  deferred.
- Package resolver, registry, lockfile, and network fetch policy remain
  out-of-core.

## Release Gates

Local macOS gate before tagging:

```sh
make all
make check
make qstar-self-host-tests
make qstar-public-beta-release-tests
git diff --check
./build/bin/qstar --version
```

Linux asset publication:

```sh
gh workflow run linux-validation.yml \
  --ref v0.7.10-beta \
  -f release_tag=v0.7.10-beta \
  -f publish_linux_asset=true
```

Windows official beta asset publication:

```sh
gh workflow run windows-validation.yml \
  --ref v0.7.10-beta \
  -f release_tag=v0.7.10-beta \
  -f publish_windows_asset=true
```

The Windows job must publish `qstar-v0.7.10-beta-windows-x86_64.zip`, then run
download smoke from the GitHub Release asset. The release decision artifact
must report:

```txt
windows_release_asset status=published
download_smoke=ok
```

## Compatibility

This patch does not add a new public DSL feature. It only tightens release
automation and cross-platform smoke handling for the existing 0.7 beta surface.
