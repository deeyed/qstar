# QStar v0.6.0 Beta

QStar v0.6.0 Beta is a public prerelease for the standalone QStar build system.
This line promotes the persistent Stella daemon from hidden experimental work to
a documented beta opt-in workflow while keeping the default `qstar build` path on
the regular Stella executor.

This release remains a beta. The only intended public binary asset for this
release is the macOS arm64 runtime tarball.

## Release Decision

Runtime version:

```txt
qstar 0.6.0-beta
```

Primary asset:

```txt
qstar-v0.6.0-beta-macos-arm64.tar.gz
```

Linux has validation-backed source builds, Ubuntu gcc/clang CI, release-candidate
tarball dry-runs, extracted tarball smoke, explicit Ninja backend parity, and
Stella/Ninja medium performance artifacts. Linux binary publication is still
deferred. Windows remains a manual native validation candidate and has no public
asset in this release.

## Highlights

- Stella daemon is now a documented beta opt-in feature.
- Normal `qstar build` still uses regular Stella; daemon residency is explicit.
- `qstar build --use-daemon=auto|always --daemon-socket path` can use a running
  daemon.
- `qstar daemon --query method` exposes read-only IDE/AI methods:
  `hello`, `workspace.info`, `targets.list`, `diagnostics.list`,
  `compile_commands.path`, and `build.summary`.
- Build output keeps CMake-style progress lines and warning/error coloring.
- Stella, Stella daemon, and Ninja are measured through medium/large performance
  line protocol gates.
- The Ninja backend covers C/C++/ASM, generated/custom actions, staticlib,
  sharedlib, executable/test, groups, run targets, and stage/install producer
  integration.
- external language backend support remains Stella-only for this beta; Ninja wrapper lowering
  is deferred while the language provider contract continues to move.
- QStar self-host remains a regular beta gate while the Makefile stays the
  canonical bootstrap and release build path.

## Stella Daemon Status

The daemon is beta opt-in, not default-on.

Supported beta host surface:

- macOS: Unix domain socket, `posix_spawn`, `poll`, `kqueue` watcher path.
- Linux: Unix domain socket, `posix_spawn`, `poll`, `inotify` validation path.
- Windows: named pipe support is deferred.

Windows named pipe support is deferred.

Linux daemon socket validation is available as an opt-in CI lane through
`.github/workflows/linux-validation.yml` with `workflow_dispatch` input
`daemon_socket_smoke=true`. It is validation-backed, not a default release gate.

The daemon read API does not expose build/test/clean mutation. It is intended as
a conservative IDE/AI bridge for reading workspace and build graph state.

Security and lifecycle gaps remain before any default-on decision:

- background start/stop/status lifecycle;
- stable daemon API version promise;
- Linux daemon socket/watcher CI lane;
- Windows named pipe ACL policy.

## Install

```sh
tar -xzf qstar-v0.6.0-beta-macos-arm64.tar.gz -C "$HOME/.local"
export PATH="$HOME/.local/bin:$PATH"
qstar --version
```

Expected version:

```txt
qstar 0.6.0-beta
```

## Release Gates

The local release gates for this beta are:

```sh
make all
make check
make qstar-self-host-tests
make qstar-medium-project-readiness-tests
make qstar-public-beta-release-tests
git diff --check
```

Socket-enabled host bonus gates:

```sh
QSTAR_TEST_QSTAR=build/bin/qstar sh tests/smoke.sh
QSTAR_TEST_QSTAR=build/bin/qstar sh tests/medium-project-performance.sh
```

`make qstar-public-beta-release-tests` verifies the installed runtime,
documentation, manpages, macOS ad-hoc codesign, tarball layout, `SHA256SUMS`, and
the policy that VSCode `.vsix` packages are not bundled into the runtime
tarball.

After the GitHub release is published, maintainers verify the uploaded asset with:

```sh
make qstar-public-beta-download-smoke
```

This downloads the release tarball and `SHA256SUMS` from GitHub, checks the
checksum, extracts into a temporary prefix, and verifies `qstar --version`,
installed docs, manpages, and macOS codesign.

## Deferred Before v1.0

- Linux and Windows public release assets.
- Windows native process/path/shared library/install validation.
- Linux daemon socket lane promotion from opt-in validation to release-backed
  gate.
- Daemon default-on lifecycle policy.
- Stable daemon protocol version promise.
- Broader CI/release matrix across macOS, Linux, and Windows.

The QStar 1.0 milestone remains reserved for validated release artifacts and CI
coverage on all major host platforms.
