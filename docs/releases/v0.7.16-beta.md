# QStar v0.7.16 Beta

QStar v0.7.16 Beta is a public prerelease patch for the 0.7 beta line. It keeps
the runtime surface compatible with v0.7.0-beta through v0.7.15-beta while
making the Windows downloaded-release smoke independent from MSYS2 compiler
runtime discovery.

Runtime version:

```txt
qstar 0.7.16-beta
```

## Release Decision

This patch release exists because `v0.7.15-beta` still failed in the
downloaded Windows release smoke. The Windows baseline job was green and the
release upload itself succeeded, but the downloaded smoke tried to build the
scaffolded `qstar init app` project by forwarding to the host GCC from inside a
QStar-launched action. On MSYS2 that process tree could still fail while
locating GCC's internal `cc1` program.

The baseline Windows job already verifies real compiler execution, Windows
process handling, shared library artifacts, and release package extraction.
The downloaded-release smoke has a narrower job: prove that the uploaded zip can
be downloaded, checksum-verified, extracted, run as `qstar.exe`, read installed
docs/man/provider files, vendor a provider through `qstar init`, and execute
Stella/Ninja actions from the extracted binary.

For that narrower contract, the downloaded Windows smoke now writes a small
fake `cc` tool that materializes object, depfile, and linked output paths
without depending on MSYS2 GCC internals. The workflow artifact also preserves
download-smoke `*.err` files so a future failure does not hide the failing
action stderr.

The `v0.7.0-beta`, `v0.7.1-beta`, `v0.7.2-beta`, `v0.7.3-beta`,
`v0.7.4-beta`, `v0.7.5-beta`, `v0.7.6-beta`, `v0.7.7-beta`,
`v0.7.8-beta`, `v0.7.9-beta`, `v0.7.10-beta`, `v0.7.11-beta`,
`v0.7.12-beta`, `v0.7.13-beta`, `v0.7.14-beta`, and `v0.7.15-beta` tags must
not be moved. Instead, `v0.7.16-beta` is the first 0.7 patch tag that contains:

- the Q253 Windows publish/download smoke path
- Windows default executable/test `.exe` artifact naming in the graph artifact
  map and cache output list
- a Windows daemon deferred status line compatible with the cross-platform
  smoke contract
- Windows-aware smoke expectations for executable artifact paths in Stella,
  Ninja, action-description, replay, command argv, and project fixture checks
- MSYS2 argv conversion protection for QStar label arguments in the broad smoke
  script using the literal `//` prefix
- host compiler selection for the toolset provider namespace wire corpus
- Windows release publication gates scoped to Windows-native validation and
  downloaded release asset smoke instead of the full broad `make check`
- checksum filename normalization for Windows/MSYS2 release uploads
- fake compiler materialization for downloaded Windows release build smoke
- downloaded Windows release smoke stderr artifact preservation

## Highlights

- Keeps `.exe` as the correct default Windows executable/test artifact suffix.
- Keeps the broad smoke script cross-platform while preserving QStar label
  arguments under MSYS2.
- Keeps GitHub Release mutation explicit: Windows upload runs only from
  `workflow_dispatch` with `publish_windows_asset=true`.
- Keeps Windows release publication focused on Windows-native build, execution,
  path/process, artifact, package, and downloaded-asset smoke evidence.
- Downloaded Windows zip smoke verifies `bin/qstar.exe`, docs/man files,
  bundled language providers, `qstar init app`, Zig provider vendoring, Stella
  build, and Ninja build from the extracted release tree.
- macOS and Linux remain ordinary 0.7 beta release assets.
- Daemon remains beta opt-in. Windows named pipe daemon support remains
  deferred.
- Package resolver, registry, lockfile, and network fetch policy remain
  out-of-core.

## Release Gates

Local macOS gate before tagging:

```sh
make all
make check
make qstar-self-host-tests
make qstar-public-beta-release-tests
git diff --check
./build/bin/qstar --version
```

Linux asset publication:

```sh
gh workflow run linux-validation.yml \
  --ref v0.7.16-beta \
  -f release_tag=v0.7.16-beta \
  -f publish_linux_asset=true
```

Windows official beta asset publication:

```sh
gh workflow run windows-validation.yml \
  --ref v0.7.16-beta \
  -f release_tag=v0.7.16-beta \
  -f publish_windows_asset=true
```

The Windows job must publish `qstar-v0.7.16-beta-windows-x86_64.zip`, then run
download smoke from the GitHub Release asset. The release decision artifact
must report:

```txt
windows_release_asset status=published
download_smoke=ok
```

## Compatibility

This patch does not add a new public DSL feature. It only tightens release
automation and downloaded Windows release smoke handling for the existing 0.7
beta surface.
