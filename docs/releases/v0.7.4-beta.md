# QStar v0.7.4 Beta

QStar v0.7.4 Beta is a public prerelease patch for the 0.7 beta line. It keeps
the runtime surface compatible with v0.7.0-beta through v0.7.3-beta while
closing another Windows publish gate issue found during the official
`windows-x86_64.zip` release path.

Runtime version:

```txt
qstar 0.7.4-beta
```

## Release Decision

This patch release exists because `v0.7.3-beta` fixed the Windows daemon
deferred status contract, but the native Windows publish gate then exposed a
third release-lane issue: the runtime now correctly emits default Windows
executables as `.exe`, while some cross-platform smoke expectations still
hard-coded POSIX executable artifact names such as
`build/qstar/out/___app/app`.

The `v0.7.0-beta`, `v0.7.1-beta`, `v0.7.2-beta`, and `v0.7.3-beta` tags must
not be moved. Instead, `v0.7.4-beta` is the first 0.7 patch tag that contains:

- the Q253 Windows publish/download smoke path
- Windows default executable/test `.exe` artifact naming in the graph artifact
  map and cache output list
- a Windows daemon deferred status line compatible with the cross-platform
  smoke contract
- Windows-aware smoke expectations for executable artifact paths in Stella,
  Ninja, action-description, replay, command argv, and project fixture checks

## Highlights

- Keeps `.exe` as the correct default Windows executable/test artifact suffix.
- Makes cross-platform smoke and Ninja parity expectations follow the host
  executable suffix instead of assuming POSIX names.
- Keeps POSIX shared-library runtime smoke on macOS/Linux while relying on the
  dedicated Windows sharedlib corpus for `.dll` and import `.lib` validation.
- Keeps GitHub Release mutation explicit: Windows upload runs only from
  `workflow_dispatch` with `publish_windows_asset=true`.
- Downloaded Windows zip smoke verifies `bin/qstar.exe`, docs/man files,
  bundled language providers, `qstar init app`, Zig provider vendoring, Stella
  build, and Ninja build from the extracted release tree.
- macOS and Linux remain ordinary 0.7 beta release assets.
- Daemon remains beta opt-in. Windows named pipe daemon support remains
  deferred.
- Package resolver, registry, lockfile, and network fetch policy remain
  out-of-core.

## Release Gates

Local macOS gate before tagging:

```sh
make all
make check
make qstar-self-host-tests
make qstar-public-beta-release-tests
git diff --check
./build/bin/qstar --version
```

Linux asset publication:

```sh
gh workflow run linux-validation.yml \
  --ref v0.7.4-beta \
  -f release_tag=v0.7.4-beta \
  -f publish_linux_asset=true
```

Windows asset publication:

```sh
gh workflow run windows-validation.yml \
  --ref v0.7.4-beta \
  -f release_tag=v0.7.4-beta \
  -f publish_windows_asset=true
```

The Windows run must upload `qstar-windows-x86_64-published-release-asset` and
write `windows-hosted-release-decision.txt` containing:

```txt
windows_release_asset status=published
download_smoke=ok
```

This is the Windows official beta asset evidence gate for the selected release
tag.

After assets are published, maintainers verify uploaded assets with:

```sh
QSTAR_RELEASE_PLATFORM=macos-arm64 QSTAR_RELEASE_TAG=v0.7.4-beta \
  make qstar-public-beta-download-smoke
QSTAR_RELEASE_PLATFORM=linux-x86_64 QSTAR_RELEASE_TAG=v0.7.4-beta \
  make qstar-public-beta-download-smoke
QSTAR_RELEASE_PLATFORM=windows-x86_64 QSTAR_RELEASE_TAG=v0.7.4-beta \
  make qstar-public-beta-download-smoke
```

The Linux smoke must run on Linux. The Windows smoke must run on a
Windows/MSYS2 host.

## Deferred Before v1.0

- Repeated macOS/Linux/Windows release matrix runs on the final v1 branch/tag.
- Stable compatibility/removal policy enforcement across docs/wiki/man/smoke.
- GLP provider-author API freeze or version negotiation.
- Daemon stable/default boundary.
- Windows named pipe daemon.
- MSVC/Visual Studio release lane.
- Windows PDB/debug artifact ownership.
- Package resolver, registry, lockfile, and network fetch.
