# QStar v0.5.2 Beta 1 Candidate Notes

QStar v0.5.2 Beta 1 is the recommended next beta patch candidate if the Stella
daemon readiness gate is accepted.

This candidate does not make the daemon the default build path. It documents the
daemon as a beta opt-in workflow for users, IDEs, and AI tooling that explicitly
choose it.

## Release Decision

Use `0.5.2-beta.1` rather than `0.6.0-beta.1`.

Reasons:

- Q145-Q150 add meaningful daemon workflow coverage, but do not change the
  default `qstar build` behavior.
- `qstar daemon --query ...` is a read-only IDE/API bridge, not a stable remote
  service contract.
- Background lifecycle, socket permission hardening, protocol versioning, and
  Windows named pipe support remain deferred.

`0.6.0-beta.1` should be reconsidered when daemon lifecycle and security are
strong enough to discuss default-on or first-class IDE service behavior.

## Highlights

- Stella daemon is now a documented beta opt-in candidate.
- Normal `qstar build` still uses the regular Stella executor path.
- `qstar build --use-daemon=auto|always --daemon-socket path` remains explicit.
- `qstar daemon --query method` exposes read-only IDE/AI methods:
  `hello`, `workspace.info`, `targets.list`, `diagnostics.list`,
  `compile_commands.path`, and `build.summary`.
- The read API does not run build/test/clean actions.
- macOS is the primary tested daemon host.
- Linux daemon validation is underway through source/CI paths.
- Windows named pipe support is deferred.

## Security Notes

Before daemon can become default-on or stable:

- socket owner and permission checks need hardening;
- stale pid/socket cleanup needs a regular lifecycle command;
- protocol version mismatch should be explicit;
- package root and build directory mismatch rejection needs more tests;
- Windows named pipe ACL policy is still deferred;
- remote daemon access remains out of scope.
