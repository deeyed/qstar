# QStar v0.7.0 Beta

This is the release note for the QStar `v0.7.0-beta` feature beta line. Round
Q169 sealed `docs/qstar-v0.7-readiness.md` with local timing, platform,
self-host, and package smoke results. Round Q170 publishes the macOS arm64
runtime asset first. Round Q171 then publishes the Linux x86_64 beta asset from
the hosted Ubuntu release lane and verifies the uploaded GitHub release asset
from the same path users download.

Runtime version:

```txt
qstar 0.7.0-beta
```

## Release Decision

`0.7.0-beta` is the active feature beta line after `0.6.1-beta`.
`0.6.x-beta` should be reserved for release/package/documentation hotfixes.

## Highlights

- Windows artifact policy is documented as a pre-support contract.
- Windows artifact policy tests now cover explicit `.exe` metadata, fake static
  `.lib` Stella/Ninja builds, and sharedlib diagnostic parity.
- Windows native alpha moves from broad preparation to a tracked failure list.
- Windows native alpha no longer stops at the Unix socket daemon source boundary;
  `_WIN32` builds compile a daemon stub and keep named pipe support deferred.
- macOS arm64 is a published beta asset for this release.
- Linux x86_64 is a published beta asset for this release. It was produced by
  the hosted Ubuntu release lane and verified after upload.
- Linux x86_64 asset smoke covers the extracted tarball and the uploaded GitHub
  release asset, including `SHA256SUMS`, `file(1)`, `ldd(1)`, docs/wiki, and
  manpage reports.
- Linux gcc/clang depfile validation remains part of the platform gate through
  the `QSTAR_LINUX_VALIDATION_CC` workflow matrix.
- Stella daemon remains beta opt-in, with lifecycle/security readiness tightened.
- Linux daemon opt-in validation records Unix socket, `inotify` watcher trace,
  and skip/fail reason artifacts.
- Stella/Ninja performance reports cover medium and large project shapes.
- Sharedlib support remains sealed for macOS/Linux. Q168 adds regression coverage
  for sharedlib-linked executable/test consumers and stage/install artifact
  handling, while Windows `.dll`/import `.lib` stays deferred until the
  multi-artifact model is implemented.

Linux asset candidates must be produced on Ubuntu or a clean Linux x86_64 host:

```sh
make all
make check
make qstar-linux-validation-tests
make qstar-ninja-backend-parity-tests
QSTAR_RELEASE_PLATFORM=linux-x86_64 QSTAR_RELEASE_TAG=v0.7.0-beta \
  tools/package-public-beta.sh
```

The Linux package gate must record both installed-tree and extracted-tarball
smoke reports: ELF x86-64 `file(1)`, `ldd(1)`, docs path, AI index, wiki home,
Lua reference, and manpage files.

After the GitHub release is published, uploaded assets must pass:

```sh
QSTAR_RELEASE_PLATFORM=macos-arm64 QSTAR_RELEASE_TAG=v0.7.0-beta \
  make qstar-public-beta-download-smoke
```

After the Linux asset is attached, run:

```sh
QSTAR_RELEASE_PLATFORM=linux-x86_64 QSTAR_RELEASE_TAG=v0.7.0-beta \
  make qstar-public-beta-download-smoke
```

The Linux publish workflow should rerun that download smoke immediately after
upload and upload `download-smoke-linux-x86_64` reports so the public asset is
checked from the same path users receive.

Round Q171 hosted verification strengthens that rule: the Linux workflow must
upload gcc/clang install-smoke reports, medium performance summaries with
`perf_summary status=ok`, downloaded tarball `contents.txt`, download-smoke
stdout, and `linux-hosted-release-decision.txt`. For `v0.7.0-beta`, that
decision file records `linux_release_asset status=published` and
`download_smoke=ok`.

## Wiki Sync

The GitHub Wiki should be synced from the repository `wiki/` tree during the
release round:

```sh
tools/sync-github-wiki.sh
```

Windows remains alpha until native source build, install smoke, artifact policy,
and release packaging are green with real Windows tools.

## Deferred Before v1.0

- Windows public release asset.
- Windows runtime `.dll`, import `.lib`, and PDB/debug artifact implementation.
- Daemon default-on policy.
- Stable daemon protocol version promise.
- Windows named pipe daemon.
- Remote daemon access.
- external language Ninja wrapper lowering while external language provider contracts are still moving.
- Package resolver, registry, and lockfile support.
