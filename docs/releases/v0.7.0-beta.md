# QStar v0.7.0 Beta

This is the release-prep note for the next QStar feature beta line. It should
not be published until `docs/qstar-v0.7-readiness.md` is refreshed with final
timing, platform, and package smoke results.

Runtime version:

```txt
qstar 0.7.0-beta
```

## Release Decision

`0.7.0-beta` is the active feature beta line after `0.6.1-beta`.
`0.6.x-beta` should be reserved for release/package/documentation hotfixes.

## Planned Highlights

- Windows artifact policy is documented as a pre-support contract.
- Windows native alpha moves from broad preparation to a tracked failure list.
- macOS arm64 and Linux x86_64 remain public beta asset hosts.
- Stella daemon remains beta opt-in, with lifecycle/security readiness tightened.
- Stella/Ninja performance reports cover medium and large project shapes.
- Sharedlib support remains sealed for macOS/Linux, while Windows `.dll`/import `.lib` stays
  deferred until the multi-artifact model is implemented.

## Release Gates

```sh
make all
make check
make qstar-self-host-tests
make qstar-medium-project-readiness-tests
make qstar-large-project-performance-tests
make qstar-public-beta-release-tests
git diff --check
./build/bin/qstar --version
```

Linux asset candidates must be produced on Ubuntu or a clean Linux x86_64 host:

```sh
make all
make check
make qstar-linux-validation-tests
make qstar-ninja-backend-parity-tests
QSTAR_RELEASE_PLATFORM=linux-x86_64 QSTAR_RELEASE_TAG=v0.7.0-beta \
  tools/package-public-beta.sh
```

After the GitHub release is published, uploaded assets must pass:

```sh
QSTAR_RELEASE_PLATFORM=macos-arm64 QSTAR_RELEASE_TAG=v0.7.0-beta \
  make qstar-public-beta-download-smoke
QSTAR_RELEASE_PLATFORM=linux-x86_64 QSTAR_RELEASE_TAG=v0.7.0-beta \
  make qstar-public-beta-download-smoke
```

Windows remains alpha until native source build, install smoke, artifact policy,
and release packaging are green with real Windows tools.

## Deferred Before v1.0

- Windows public release asset.
- Windows runtime `.dll`, import `.lib`, and PDB/debug artifact implementation.
- Daemon default-on policy.
- Stable daemon protocol version promise.
- Windows named pipe daemon.
- Remote daemon access.
- Cale Ninja wrapper lowering while Cale provider contracts are still moving.
- Package resolver, registry, and lockfile support.
