# QStar v0.7.2 Beta

QStar v0.7.2 Beta is a public prerelease patch for the 0.7 beta line. It keeps
the runtime surface compatible with v0.7.0-beta and v0.7.1-beta while fixing a
Windows executable artifact naming bug that blocked the official
`windows-x86_64.zip` publication gate.

Runtime version:

```txt
qstar 0.7.2-beta
```

## Release Decision

This patch release exists because `v0.7.1-beta` added the Windows official beta
asset publication path, but the native Windows publish gate exposed a stale
artifact policy gap: default executable/test targets on Windows planned their
primary artifact as `app` while the platform toolchain produced `app.exe`.
That made Stella cache-hit validation rerun the link action because the tracked
output path was missing.

The `v0.7.0-beta` and `v0.7.1-beta` tags must not be moved. Instead,
`v0.7.2-beta` is the first 0.7 patch tag that contains both the Q253
publish/download smoke path and the Windows executable artifact cache fix.

## Assets

```txt
qstar-v0.7.2-beta-macos-arm64.tar.gz
qstar-v0.7.2-beta-linux-x86_64.tar.gz
qstar-v0.7.2-beta-windows-x86_64.zip
SHA256SUMS
```

## Highlights

- Fixes Windows default executable/test artifact names so they use `.exe` in
  the graph artifact map, cache output list, action logs, dry-runs, and release
  smoke paths.
- Keeps GitHub Release mutation explicit: Windows upload runs only from
  `workflow_dispatch` with `publish_windows_asset=true`.
- Downloaded Windows zip smoke verifies `bin/qstar.exe`, docs/man files,
  bundled language providers, `qstar init app`, Zig provider vendoring, Stella
  build, and Ninja build from the extracted release tree.
- macOS and Linux remain ordinary 0.7 beta release assets.
- Daemon remains beta opt-in. Windows named pipe daemon support remains
  deferred.
- Package resolver, registry, lockfile, and network fetch policy remain
  out-of-core.

## Release Gates

Local macOS gate before tagging:

```sh
make all
make check
make qstar-self-host-tests
make qstar-public-beta-release-tests
git diff --check
./build/bin/qstar --version
```

Linux asset publication:

```sh
gh workflow run linux-validation.yml \
  --ref v0.7.2-beta \
  -f release_tag=v0.7.2-beta \
  -f publish_linux_asset=true
```

Windows asset publication:

```sh
gh workflow run windows-validation.yml \
  --ref v0.7.2-beta \
  -f release_tag=v0.7.2-beta \
  -f publish_windows_asset=true
```

The Windows run must upload `qstar-windows-x86_64-published-release-asset` and
write `windows-hosted-release-decision.txt` containing:

```txt
windows_release_asset status=published
download_smoke=ok
```

This is the Windows official beta asset evidence gate for the selected release
tag.

After assets are published, maintainers verify uploaded assets with:

```sh
QSTAR_RELEASE_PLATFORM=macos-arm64 QSTAR_RELEASE_TAG=v0.7.2-beta \
  make qstar-public-beta-download-smoke
QSTAR_RELEASE_PLATFORM=linux-x86_64 QSTAR_RELEASE_TAG=v0.7.2-beta \
  make qstar-public-beta-download-smoke
QSTAR_RELEASE_PLATFORM=windows-x86_64 QSTAR_RELEASE_TAG=v0.7.2-beta \
  make qstar-public-beta-download-smoke
```

The Linux smoke must run on Linux. The Windows smoke must run on a
Windows/MSYS2 host.

## Platform Status

| Host platform | Status |
| --- | --- |
| macOS arm64 | Beta release artifact |
| Linux x86_64 | Beta release artifact from hosted Ubuntu publication lane |
| Windows x86_64 | Official beta asset after `publish_windows_asset=true` succeeds |

## Deferred Before v1.0

- Repeated macOS/Linux/Windows release matrix runs on the final v1 branch/tag.
- Stable compatibility/removal policy enforcement across docs/wiki/man/smoke.
- GLP provider-author API freeze or version negotiation.
- Daemon stable/default boundary.
- Windows named pipe daemon.
- MSVC/Visual Studio release lane.
- Windows PDB/debug artifact ownership.
- Package resolver, registry, lockfile, and network fetch.
