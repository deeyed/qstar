# QStar v0.5.1 Beta 1

QStar v0.5.1 Beta 1 is a beta patch release candidate for QStar as a standalone
build system.

This release remains a beta. The macOS arm64 binary is the only intended public
binary artifact for this prerelease. Linux has a validation-backed source build
path and a `linux-x86_64` release-candidate packaging dry-run, but no Linux
binary is published by default. The Linux validation workflow also collects
Stella/Ninja medium performance line protocol artifacts on Ubuntu gcc/clang
lanes. Windows has native validation prep and path / process contracts, but no
official host support or binary artifact yet.

## Release Decision

This line uses `0.5.1-beta.1` rather than `0.5.0-beta.2` because the Q115-Q116
work added user-facing beta surface:

- `qstar.sharedlib` policy is now documented and tested for Darwin-like
  `.dylib` and Linux-like `.so` builds through Stella and Ninja.
- external language backend behavior is now an explicit contract: external sources are
  Stella-only language-provider actions for this release, and Ninja wrapper
  lowering is deferred.
- Linux and Windows readiness are updated from loose platform notes into
  release-trackable validation paths.

## Highlights

- Runtime version is `qstar 0.5.1-beta.1`.
- Stella remains the default native executor.
- Ninja backend remains available with `-G ninja` and is covered by parity
  tests for C/C++/ASM compile, generated/configure actions, static libraries,
  shared libraries on Darwin/Linux-like profiles, executable/test links, run
  targets, groups, and compile database output.
- `qstar.sharedlib` supports Darwin-like `.dylib` and Linux-like `.so` policy
  through Stella and Ninja. Windows `.dll`, import-library, and PDB policy
  remains deferred.
- external language backend support is intentionally Stella-only for this beta. QStar still
  treats header-language as an opaque header-like input path and does not interpret header-language.
- Smoke diagnostics now print narrower test step labels and better failure
  context, so release-gate failures are easier to locate.
- Linux release-candidate packaging dry-run validates ELF x86-64 shape, `ldd`,
  installed docs/wiki/manpages, and `SHA256SUMS`.
- Linux gcc/clang CI lanes collect Stella/Ninja medium performance artifacts and
  verify the POSIX `posix_spawn` plus `poll` runner trace.
- Performance gates now also record the experimental Stella daemon path as
  `backend=stella-daemon` for medium and large corpus clean/no-op/incremental
  phases. Daemon timing remains report-only and is skipped with an explicit
  `socket-bind-not-permitted` reason in sandboxed hosts.
- Windows prep now has documented path normalization, process quoting,
  response-file, and artifact naming rules, but remains non-official.

## Install

```sh
tar -xzf qstar-v0.5.1-beta.1-macos-arm64.tar.gz -C "$HOME/.local"
export PATH="$HOME/.local/bin:$PATH"
qstar --version
```

Expected version:

```txt
qstar 0.5.1-beta.1
```

The tarball uses a prefix install layout and includes `bin/qstar`, installed
wiki, manpages, README files, Apache-2.0 license text, and the Lua vendor
license notice. The release also publishes `SHA256SUMS`.

## Validate

```sh
qstar init c-app /tmp/qstar-hello
qstar --file /tmp/qstar-hello/qstar.lua build //:app --progress plain
/tmp/qstar-hello/build/qstar/out/___app/app
```

The local release gates for this beta patch are:

```sh
make check
make qstar-public-beta-release-tests
make qstar-self-host-tests
make qstar-medium-project-readiness-tests
make vscode-extension-tests
```

`make qstar-public-beta-release-tests` verifies the installed runtime,
docs/wiki, manpages, macOS codesign, tarball layout, and `SHA256SUMS` before
publication. VSCode extension packaging is verified separately and remains out
of the runtime tarball.

## Platform Status

| Host platform | Status |
| --- | --- |
| macOS arm64 | Beta release artifact |

QStar 1.0 is reserved for validated release artifacts and CI coverage across
macOS, Linux, and Windows.

```txt
medium_project_gate compare phase=noop stella_ms=67 ninja_ms=73 ratio_x100=200 slack_ms=250
medium_project_gate compare phase=incremental stella_ms=89 ninja_ms=97 ratio_x100=200 slack_ms=250
medium_project_gate compare backend=stella-jobs phase=clean stella_ms=237 ninja_ms=251 ratio_x100=200 slack_ms=250
medium_project_gate compare backend=stella-jobs phase=noop stella_ms=68 ninja_ms=73 ratio_x100=200 slack_ms=250
medium_project_gate compare backend=stella-jobs phase=incremental stella_ms=88 ninja_ms=97 ratio_x100=200 slack_ms=250
medium_project_gate status=ok perf_issue_count=0 report_only=1
```

Stella's no-op and incremental paths stayed near Ninja-level latency on the
medium corpus. The Q137 representative run also put Stella clean builds inside
the 1.5x target on this host. Timing thresholds remain report-only for this beta
patch because small corpus results are sensitive to host CPU, filesystem cache,
and compiler warm state.

Linux CI now collects the same medium corpus as line protocol artifacts for both
gcc and clang lanes:

```txt
dist/perf/linux-<compiler>-medium-perf.txt
dist/perf/linux-<compiler>-medium-summary.txt
dist/perf/linux-<compiler>-medium-summary.md
```

The CI hard check is structural rather than a timing threshold: Stella must
report `medium_project_gate scheduler runner=posix_spawn event_wait=poll`, and
the Ninja clean phase must appear in the same output. Large synthetic Linux
performance remains an on-demand `workflow_dispatch` report artifact.

Q149 extends the same summary format to daemon timing. A release-note-ready
summary can be generated with:

```sh
tools/perf-summary.sh --repeat 3 -- \
  env QSTAR_TEST_QSTAR=./build/bin/qstar sh tests/medium-project-performance.sh
```

## VSCode Extension

The VSCode extension is versioned independently from the runtime. For this
runtime beta patch, the extension package remains `qstar-vscode 0.3.0` and is
not included as a GitHub release asset.

## Notes

- The Makefile remains QStar's canonical bootstrap and release build path.
- The QStar self-host graph is a backend parity and release-gate validation
  path, not a replacement for the Makefile release binary.
- Linux validation and packaging dry-run are active, but Linux release artifacts
  still require an explicit publication decision after a clean Linux release
  host or CI packaging lane is green. Medium performance artifacts are collected
  in CI, but timing thresholds remain report-only.
- Windows path/process rules are documented as a pre-port contract, but no
  Windows artifact is published in this prerelease.
- QStar is licensed under Apache-2.0. Lua vendor license text is preserved in
  `LICENSE/lua.txt`.
