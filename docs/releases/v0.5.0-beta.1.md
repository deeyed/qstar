# QStar v0.5.0 Beta 1

QStar v0.5.0 Beta 1 is a prerelease of QStar as a standalone build system.

This release is a beta. The macOS arm64 binary is the only published binary
artifact for this prerelease. Linux has a validation-backed source build path
through Ubuntu gcc/clang CI, Windows host support is planned, and both still
need release artifact validation before QStar 1.0.

## Highlights

- Runtime version is `qstar 0.5.0-beta.1`.
- Stella remains the default native executor.
- Ninja backend remains available with `-G ninja` and is covered by parity
  tests for C/C++/ASM compile, generated/configure actions, static libraries,
  executable/test links, run targets, groups, and compile database output.
- QStar self-host is now part of the beta gate: Makefile-built and QStar-built
  binaries must report the same `--version` through Stella and Ninja paths.
- Medium project performance gates record Stella and Ninja clean, no-op, and
  incremental timings in a release-trackable line protocol.
- Linux validation is backed by the Ubuntu gcc/clang workflow and
  `make qstar-linux-validation-tests`, but no Linux binary asset is published in
  this prerelease.
- Public beta packaging verifies installed docs/wiki, manpages, macOS codesign,
  prefix tarball layout, `SHA256SUMS`, and the policy that VSCode `.vsix`
  artifacts are not included in the runtime tarball.

## Install

```sh
tar -xzf qstar-v0.5.0-beta.1-macos-arm64.tar.gz -C "$HOME/.local"
export PATH="$HOME/.local/bin:$PATH"
qstar --version
```

Expected version:

```txt
qstar 0.5.0-beta.1
```

The tarball uses a prefix install layout and includes `bin/qstar`, installed
wiki, manpages, README files, Apache-2.0 license text, and the Lua vendor
license notice. The release also publishes `SHA256SUMS`.

## Validate

```sh
qstar init c-app /tmp/qstar-hello
qstar --file /tmp/qstar-hello/qstar.lua build //:app --progress plain
/tmp/qstar-hello/build/qstar/out/___app/app
```

The local release gates used for this beta are:

```sh
make qstar-public-beta-release-tests
make qstar-self-host-tests
make qstar-medium-project-readiness-tests
```

`make qstar-public-beta-release-tests` verifies the installed runtime,
docs/wiki, manpages, macOS codesign, tarball layout, and `SHA256SUMS` before
publication.

## Platform Status

| Host platform | Status |
| --- | --- |
| macOS arm64 | Beta release artifact |
| Linux | Validation-backed source build through Ubuntu gcc/clang CI |
| Windows | Planned validation |

QStar 1.0 is reserved for validated release artifacts and CI coverage across
macOS, Linux, and Windows.

## Performance Snapshot

Round Q110 local macOS arm64 medium corpus timing:

```txt
medium_project_gate backend=stella phase=clean elapsed_ms=767
medium_project_gate backend=stella phase=noop elapsed_ms=73
medium_project_gate backend=stella phase=incremental elapsed_ms=101
medium_project_gate backend=ninja phase=clean elapsed_ms=299
medium_project_gate backend=ninja phase=noop elapsed_ms=74
medium_project_gate backend=ninja phase=incremental elapsed_ms=101
medium_project_gate status=ok perf_issue_count=0 report_only=1
```

Stella's no-op and incremental paths are at Ninja-level latency on this corpus.
Clean builds remain slower than Ninja, but still complete in under one second on
this medium fixture.

## VSCode Extension

The VSCode extension is versioned independently from the runtime. For this
runtime beta, the extension package remains `qstar-vscode 0.3.0` and is not
included as a GitHub release asset.

## Notes

- The Makefile remains QStar's canonical bootstrap and release build path.
- The QStar self-host graph is a backend parity and release-gate validation
  path, not a replacement for the Makefile release binary.
- Linux validation is active, but Linux release artifacts require a clean Linux
  release host or CI packaging lane before publication.
- Windows path/process rules are documented as a pre-port contract, but no
  Windows artifact is published in this prerelease.
- QStar is licensed under Apache-2.0. Lua vendor license text is preserved in
  `LICENSE/lua.txt`.
