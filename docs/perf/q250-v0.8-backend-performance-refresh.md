# Q250 v0.8 Backend Performance Refresh

Round Q250는 GLP, Windows beta path, generic command workflow, built-in install hard cut,
daemon beta boundary hardening 이후 v0.8 공개 전에 Stella, Stella daemon, explicit-jobs
Stella, Ninja 성능을 다시 찍은 freshness snapshot이다. 이 문서는 release input이며 stable
performance guarantee가 아니다. Timing threshold는 계속 report-only다.

## Environment

```txt
date: 2026-06-21
host: macOS arm64
kernel: Darwin 25.5.0
host_jobs: 10
qstar: 0.7.0-beta
baseline commit before docs update: 26a0a37
timing policy: report-only
daemon socket: permitted local Unix socket environment
```

## Commands

```sh
make qstar-performance-release-gate
make qstar-large-project-performance-tests
make qstar-medium-project-readiness-tests
git diff --check
```

`make qstar-performance-release-gate` produced repeat-3 raw and summary artifacts under
`dist/perf`. The `dist/` tree is ignored and not committed; this document records the release-facing
summary. The daemon phases were executed in a socket-permitting local environment, so the repeat-3
tables below have no `socket-bind-not-permitted` skips.

## Interpretation

- Medium corpus has no visible regression: normal Stella, explicit-jobs Stella, Stella daemon, and
  Ninja all stay in the same latency band. Stella daemon is slightly ahead of Ninja in the three
  median phases in this run.
- Large 200-target mode is also stable: normal Stella and daemon are at or ahead of Ninja in clean,
  no-op, and incremental medians.
- Large 500-target clean is mixed: normal Stella and explicit-jobs Stella are slower than Ninja in
  the repeat-3 median (`1.20x`), while Stella daemon is faster than Ninja (`0.67x`). No-op and
  incremental remain ahead of Ninja for all Stella modes.
- The large 500 normal Stella clean median moved unfavorably compared with Q233 and the single
  post-gate validation run, while min values remain close to the old band. This points to host/load
  variance and clean-build metadata/process scheduling noise rather than a structural correctness
  failure. The result is still within the report-only release threshold.
- Daemon remains a beta opt-in fast iteration / IDE path. It should not be marketed as a guaranteed
  faster clean-build path, even though it won the large 500 clean median in this snapshot.
- README and release notes should avoid absolute performance claims. The accurate statement is that
  QStar records report-only Stella/Ninja/daemon performance artifacts and Q250 did not find a hard
  performance gate failure.
